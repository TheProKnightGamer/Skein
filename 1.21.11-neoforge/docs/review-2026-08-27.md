# Skein review — 2026-08-27

Thirty findings from a nine-dimension agent review (pool, deferral, geometry,
scheduled ticks, mixins-vs-vanilla, shared vanilla state, chunk source,
per-thread state, lifecycle). Adversarial verification and the automated fixer
were cut short by a network failure, so **these are reviewer claims, not
confirmed defects**, except where marked VERIFIED below.

## Verified by hand (read-only, against the decompiled 1.21.1 sources)

### Cross-dimension writes — seven findings, one root cause. HIGH severity.

`Entity.baseTick` (Entity.java:448) calls `handlePortal()`, so portal transit
happens *inside* the parallel entity tick. `Entity.changeDimension` then writes
to the **destination** level:

```java
serverlevel1.addDuringTeleport(entity2);              // -> addEntity on another level
serverlevel1.resetEmptyTime();
transition.postDimensionTransition().onTransition(entity2);  // -> placePortalTicket
```

`addDuringTeleport` -> `addEntity`, which `ServerLevelMixin.skein$deferSpawn`
does intercept. But `DeferredWork.defer(Level, Runnable)` **ignores its `level`
argument** and parks into the *calling thread's* buffer. So the destination
level's entity add is replayed by the *source* level's coordinator while the
destination level is being ticked concurrently by another worker.

`Entity.placePortalTicket` -> `destination.getChunkSource().addRegionTicket(...)`
mutates the destination `DistanceManager` and is not deferred at all.

And cross-level `getChunk` fails `TickContext.owns(this.level)`, so
`skein$currentOwner` returns `mainThread`, vanilla takes its off-thread branch
(`supplyAsync(..., mainThreadProcessor).join()`), and the calling worker blocks
until the destination level's processor is drained — which nobody does if that
level has finished its tick and is waiting at the barrier. Deadlock.

**Net effect: a nether/end portal can hang or corrupt the server whenever
dimension threading is on.** No benchmark in this repo used portals.

### ClusterPartition joins on the Y axis. HIGH severity.

`ClusterPartition.withinLink` tests x, y and z. Two scheduled-tick components
separated only vertically (same chunk column) become separate components and run
concurrently — but they share a `LevelChunk` and its `ChunkHolder`, whose
`changedBlocksPerSection` / `hasChangedSections` and heightmaps are
unsynchronised. The entity/random-tick grid is 2-D and does not have this
problem; only the scheduled-tick component split does. Fix: drop the Y test so
components are chunk-column disjoint.
